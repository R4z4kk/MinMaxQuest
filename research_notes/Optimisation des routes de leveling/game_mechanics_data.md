# Game mechanics and numeric data for simulating Classic / Forever leveling time

Research date: 2026-11-27. Target: World of Warcraft: Forever (client 1.60.1, Interface 16001), which is based on Classic Era (1.15.x / 1.12 rules).
Confidence scale: HIGH = primary source (emulator code or Blizzard-derived data in the local addon), MED = wiki / secondary source, LOW = unverified or memory. Values tagged **[RE-VERIFY FOREVER]** must be checked in game on Forever before they are hard-coded.

## Quest XP formula, rounding, and where base quest XP is stored

### Takeaway
QuestieDB's quest entity has **no XP field**. Base quest XP ships as separate "support" data in QuestieDB (`{questLevel, baseXP}` per questId), and Forever uses that data. Questie computes the reduction for over-leveled quests in its own module, and **Forever uses a different floor**: 100/80/60/50 %, against 100/80/60/40/20/10 % in Classic Era.

### Cited Findings
- QuestieDB quest fields (36 keys) include `requiredLevel` (4), `questLevel` (5), `objectives` (10), `zoneOrSort` (17), `requiredMaxLevel` (32) and more. There is **no XP or reward-money field**. — local file `QuestieDB\src\meta\questMeta.lua` (QuestieDB v1.1.6, `X-Flavor: Forever`, `QuestieDB_Forever.toc`)
- Base quest XP lives in `QuestieDB\support\Forever\QuestXP\xpDB-classic.lua` (generated, about 3,494 entries, format `[questId] = {questLevel, xp}`, with comments comparing Classic, TBC and WotLK values). It is overridden by `xpDB-traces.lua` (3,737 entries), which was "Generated by QuestieTrace extract… Sessions aggregated: 2512170… Generated at: 2026-11-24T10:38:01.776Z". The trace values come from real Forever player telemetry. Consumers read it through `LibQuestieDB.Support.Get("QuestXP")`. — local files under `QuestieDB\support\Forever\QuestXP\`
- Questie's adjustment (`Questie\Database\QuestXP\QuestieXP.lua`, `getAdjustedXP`):
  - `mult = 2*(qLevel - charLevel) + 20`, clamped to `[1,10]` on Era, or **`[5,10]` on Forever** (code comment: "On Forever the fractions are 100% 80% 60% 50%"). Then `xp = xp * mult / 10`.
  - Rounding: if xp <= 100, `5*floor((xp+2)/5)`; if <= 500, `10*floor((xp+5)/10)`; if <= 1000, `25*floor((xp+12)/25)`; otherwise `50*floor((xp+25)/50)`.
  - The result is multiplied by `(1 + buffs)` and floored. The listed Forever buff is "Well-Rested (Sleeping Bag in Forever)", spell 429959, +1 % per stack. Darkmoon Faire (46668) gives +10 %.
  - At max level the function returns 0. The code notes the rounding is uncertain: "some 85 xp quests should actually give 90". — local file
- Meaning of the Era formula: char <= qLevel+5 gives 100 %, +6 gives 80 %, +7 gives 60 %, +8 gives 40 %, +9 gives 20 %, +10 or more gives 10 %. On Forever: +6 gives 80 %, +7 gives 60 %, **+8 or more gives 50 %**. — derived from the local Questie code above
- vmangos `Quest::XPValue(playerLevel)` uses the same steps: `pLevel <= qLevel+5` gives `ceil(RewXP)`, +6 gives ×0.8, +7 ×0.6, +8 ×0.4, +9 ×0.2, otherwise ×0.1. It uses **ceil**, not Blizzard's 5/10/25/50 rounding. — [vmangos QuestDef.cpp](https://raw.githubusercontent.com/vmangos/core/development/src/game/QuestDef.cpp)
- At level 60, quest XP converts to gold (patch 1.10.0, "Quest Experience to Gold Conversion at Level 60"). — [vmangos QuestDef.cpp](https://raw.githubusercontent.com/vmangos/core/development/src/game/QuestDef.cpp)
- Beta reporting on Forever dungeon quests: below level 40 they paid "roughly twice their Classic experience". This was later reduced: "Bonus experience from dungeon quests was cut in half on October 1, and experience from dungeon mobs was raised by about 20 percent on October 8". — [Icy Veins (search summary)](https://www.icy-veins.com/wow-forever/news/blizzard-reveals-how-leveling-will-work-in-wow-forever/), [Destructoid (search summary)](https://www.destructoid.com/everything-you-need-to-know-about-wow-forever-leveling/). Both pages returned 403 on fetch, so this comes from search snippets only (MED-LOW).

### Inferences
- The optimizer should take base XP from `xpDB-traces.lua`, falling back to `xpDB-classic.lua`, keyed by questId and joined to QuestieDB `questLevel`. It should apply the **Forever** clamp `[5,10]` and Questie's rounding. The traces file is observed Forever data, so it already reflects any Forever dungeon-quest bonus, and the source should be cited with its generation timestamp. **[RE-VERIFY FOREVER]**: the 50 % floor comes from a single source (a Questie code comment). Confirm it in game by turning in a quest that is 8 or more levels below you.
- Because of the 50 % floor, gray quests are worth much more on Forever than in Era, so route optimizers should not drop them the way Era guides do.
- In the retail DBC model (QuestXP.dbc / RewardXPDifficulty), XP is an index into a per-level table. The 1.x / Classic Era server stores absolute XP per quest instead (vmangos `RewXP`). Questie's db already contains the absolute values, so no DBC lookup is needed.

### Gaps
- Whether Forever's quest-XP rounding matches Era (Questie's own comment calls it uncertain).
- No Blizzard primary source on Forever's gray-quest XP floor was found. The Blizzard news URL returned an unrelated retail article.

## Mob kill XP formula, gray level, elites, groups, rested XP

### Takeaway
Base kill XP is `(playerLevel*5 + 45) × levelFactor`, rounded to nearest. Elites give ×2 in the open world and ×2.5 in 5-player dungeons (vmangos). Rested XP doubles kill XP until the pool runs out. The pool fills at 5 % of a level per 8 hours resting, up to 1.5 levels.

### Cited Findings
- vmangos `Formulas.h` (HIGH) — [source](https://raw.githubusercontent.com/vmangos/core/development/src/game/Formulas.h):
  - `GetGrayLevel(pl)`: pl <= 5 gives 0; pl <= 39 gives `pl - 5 - pl/10`; otherwise `pl - 1 - pl/5` (integer division).
  - Colors: red if mob >= pl+5; orange if >= pl+3; yellow if >= pl-2; green if > gray; otherwise gray.
  - `GetZeroDifference(pl)`: <8 gives 5, <10 gives 6, <12 gives 7, <16 gives 8, <20 gives 9, <30 gives 11, <40 gives 12, <45 gives 13, <50 gives 14, <55 gives 15, <60 gives 16, otherwise 17.
  - `BaseGainLevelFactor`: if mob >= pl, `1 + 0.05*min(mob-pl, 4)`; if gray < mob < pl, `(ZD + mob - pl)/ZD`; otherwise 0.
  - `BaseGain = (pl*5 + 45) * factor`.
  - Elite: ×2.5 in non-raid dungeons, otherwise ×2.0. Pets ×0.75. Creature `xp_multiplier` is applied. The result is `nearbyint`.
  - No XP is given for summoned critters or totems, or for creatures flagged NO_XP.
  - Group rate (`xp_in_group_rate`, comment says "completely guesswork"): 1-2 members 1.0, 3 members 1.166, 4 members 1.3, 5 members 1.4.
- The wiki uses the same tables, plus the split for 2-player groups `XP_i = MXP × CL_i / (CL1+CL2)` with no bonus for two players. Its lower-level example uses the **mob** level in the base (for example level 20 vs level 18 gives 110.4, so it uses 18×5+45). vmangos uses the **player** level, which gives 118.6. — [warcraft.wiki.gg Mob experience](https://warcraft.wiki.gg/wiki/Mob_experience) (page last edited 2020). This **conflicts** with vmangos.
- Rested XP in vmangos `Player.cpp` (HIGH) — [source](https://raw.githubusercontent.com/vmangos/core/development/src/game/Objects/Player.cpp):
  - The rate is one bubble (5 % of the current level's XP) per 8 h in a rest area: `bonus = t * NEXT_LEVEL_XP/1152000` (the server stores half, and the client doubles it).
  - Offline outside a rest area, the rate is ÷4.
  - The cap is `NEXT_LEVEL_XP*1.5/2` server-side, which is 1.5 levels of rested XP as the client shows it.
  - `GetXPRestBonus(xp)` adds up to `xp` extra per kill, so at most 200 %. It is only applied when `victim` is set, which means **kills only, not quest XP**.
  - No rest accumulates at max level.
- vmangos default rest rates: `Rate.Rest.InGame = 1`, `Rate.Rest.Offline.InTavernOrCity = 1`, `Rate.Rest.Offline.InWilderness = 1`. — [vmangos mangosd.conf.dist.in](https://raw.githubusercontent.com/vmangos/core/development/src/mangosd/mangosd.conf.dist.in)
- Forever: dungeon mob XP was raised "about 20 percent" during beta (October 8). — [Icy Veins (search summary)](https://www.icy-veins.com/wow-forever/news/blizzard-reveals-how-leveling-will-work-in-wow-forever/) (MED-LOW)
- Forever adds a "Sleeping Bag" Well-Rested buff (spell 429959), which Questie treats as +1 % XP per stack. — local `Questie\Database\QuestXP\QuestieXP.lua`

### Inferences
- Optimizer kill-XP model: `xp = round((L*5+45) * factor(L, mobLvl)) * eliteMult * (rested ? 2 : 1)`. Use vmangos (player-level base). It is the most-tested emulator, and the wiki is old.
- Same-level examples: level 10 gives 95 XP per kill, level 30 gives 195, level 59 gives 340. At level 59, 209,800 XP equals about 617 same-level kills, which is a good sanity check for grind segments.
- **[RE-VERIFY FOREVER]**: mob XP (possible dungeon multiplier), the sleeping-bag buff, and the rested accumulation rate.

### Gaps
- Exact Blizzard group-bonus values are unconfirmed (vmangos calls them guesswork).
- Sleeping Bag stack count, duration and how to obtain it on Forever were not researched.
- The exact Forever multiplier on dungeon mobs is not confirmed by a primary source.

## Movement speeds, mounts, class speed abilities

### Takeaway
Base run speed is 7.0 yd/s. Mounts give +60 % (11.2 yd/s) and +100 % (14 yd/s). In Classic the mount levels are 40 and 60, but Forever changed mount pricing and training. Class travel forms are about +30 to +40 % but are only partly sourced.

### Cited Findings
- Run speed is 7 yd/s (100 %), walk 2.5 yd/s, backward 4.5 yd/s. Swimming is 67 % of base speed. — [warcraft.wiki.gg Movement speed](https://warcraft.wiki.gg/wiki/Movement_speed) (page marked outdated, but base run speed is stable)
- A normal land mount gives 160 % and a swift land mount 200 %. Sprint gives +70 %. — [warcraft.wiki.gg Movement speed](https://warcraft.wiki.gg/wiki/Movement_speed)
- Forever: the first mount costs 100 gold according to beta reporting, and "there is no free mount training at 40 this time around". Dual spec is also unlocked at 40. — [kami-labs](https://kami-labs.fr/en/wow-forever/wow-forever-niveau-40-monture-double-specialisation/), [Massively OP](https://massivelyop.com/2026/09/15/wow-forever-discusses-classes-addons-party-forming-pvp-progression-and-how-it-effectively-negates-wow-2/) (search summaries, MED-LOW)

### Inferences
- Speeds for the optimizer: foot 7.0, mount 11.2, epic 14.0 yd/s. Use about 0.8× as a terrain/pathing factor on straight-line distances, as a heuristic (LOW).
- Mount availability: level 40 (Riding 75) and level 60 (Riding 150) in Classic Era. **[RE-VERIFY FOREVER]**, because the level-40 gold cost determines whether a player can actually afford it on time.

### Gaps
- From memory, not verified in this session (LOW, do not hard-code without a check): shaman Ghost Wolf at level 20, +40 %; druid Travel Form at level 30, +40 %; hunter Aspect of the Cheetah at level 20, +30 % with a daze on hit; druid Cat Form plus the Feline Swiftness talent, +15 %. A Wowhead Classic spell lookup is needed.
- The exact Forever mount levels, costs and training changes need a primary Blizzard source.

## Flight paths, boats/zeppelins, hearthstone

### Takeaway
Taxi speed is about 430 % of run speed, roughly 30 yd/s. Flight times should be measured or extracted from client DBC path data (TaxiPath / TaxiPathNode), not computed as straight lines. The hearthstone has a 10 s cast. Its vanilla cooldown of 1 h is not confirmed by the sources reached.

### Cited Findings
- Regular taxis fly at 430-433 % (7 × 4.3 ≈ 30.1-30.3 yd/s). Flying machines fly at 287-288 %. — [warcraft.wiki.gg Movement speed](https://warcraft.wiki.gg/wiki/Movement_speed)
- Hearthstone (item 6948) has a 10 second cast. Its cooldown was "reduced to 30 minutes" in patch 3.1.0 (2009-04-14). Because this happened after vanilla, the earlier value (vanilla and Classic) was longer, but the page does not state it. — [warcraft.wiki.gg Hearthstone](https://warcraft.wiki.gg/wiki/Hearthstone)
- Questie has no taxi node or flight master dataset. A grep for TaxiNode and FlightMaster in the Questie Lua returned nothing. NPC `npcFlags` (field 15 in QuestieDB) can still identify flight masters. — local files `QuestieDB\src\meta\npcMeta.lua`, Questie

### Inferences
- Taxi graph sources: TaxiNodes.db2, TaxiPath.db2 and TaxiPathNode.db2 for the 1.15 / 1.60 build on wago.tools. Compute flight time as the polyline length divided by about 30 yd/s, plus takeoff and landing overhead, then check against measured times. Learning a new flight path requires visiting the node once, which costs travel time plus about 2 s of interaction.
- Hearthstone: 10 s cast and 60 min cooldown for Classic Era, from memory (LOW). **[RE-VERIFY FOREVER]**
- Boats and zeppelins run on cycles of about 2-5 minutes. Model each trip as an average wait of half a cycle plus the trip time. No data was found (see Gaps).

### Gaps
- No sourced boat or zeppelin schedules or trip times were found.
- No dataset of measured Classic flight times was found. A candidate approach is to compute times from wago.tools DBC exports, but this is unverified.
- Forever may add new taxi nodes, since it has new zones such as "Riverglades" (mid-30s to mid-40s). These are not covered by Era datasets. **[RE-VERIFY FOREVER]**

## Kill-time / objective-time estimation, respawns, drop rates

### Takeaway
The local QuestieDB already provides per-NPC drop chances in two forms, Wowhead-derived and cmangos-derived, plus manual corrections. Kill times and respawn timers have to come from heuristics or telemetry, since no sourced numbers were found.

### Cited Findings
- `QuestieDB\support\Forever\DropTables\classicItemDrops.lua` has two tables. `wowheadData` is "automatically generated from wowhead data based upon objective data from our DB", with the format `[itemId] = { [npcId] = dropPercent }` (for example item 159 from NPC 6 at 10.9946 %). `cmangosData` starts at line 17809. Manual overrides are in `itemDropCorrections.lua`, with the format `[itemID] = {[npcID] = 80.0}`. — local files
- QuestieDB NPC fields: `minLevel`, `maxLevel`, `rank` (elite flag), `minLevelHealth`, `maxLevelHealth`, `spawns` (`{[zoneId]={{x,y,phase?},...}}`), `waypoints`, `zoneID`, `npcFlags`. Item fields: `npcDrops`, `objectDrops`, `itemDrops`, `vendors`. — local `QuestieDB\src\meta\npcMeta.lua`, `itemMeta.lua`
- The XP formula excludes creatures flagged NO_XP and summoned critters. — [vmangos Formulas.h](https://raw.githubusercontent.com/vmangos/core/development/src/game/Formulas.h)

### Inferences
- "Collect N drops" objective: expected kills = N / p, where p = dropPercent/100. Add variance, because a geometric distribution has a long tail. Plan on a high percentile, for example kills needed for 80 % confidence.
- Kill time: model it as `mobHP / classDPS(L) + downtime`. QuestieDB's `maxLevelHealth` gives HP. DPS and downtime per class and level must be calibrated from the user's own play logs, since no source was found.
- Spawn density: count QuestieDB spawn points in the objective area. Kill rate is limited by both kill time and travel time between spawns.

### Gaps
- No sourced Classic respawn timers. Emulator `creature.spawntimesecs` is often about 5 min for open-world mobs, from memory (LOW). Classic Era also uses dynamic respawn in crowded areas, and Forever behavior is unknown.
- No sourced time-to-kill data per class and level.

## Coordinate systems and conversion to yards

### Takeaway
QuestieDB stores zone-relative percentage coordinates (0-100) per AreaID. Converting them to yards requires each map's world size, and the client provides it at runtime. Forever **changed the map frames of 4 zones**, and QuestieDB ships an explicit transform for them.

### Cited Findings
- NPC spawns are stored as `{[zoneId] = {{x, y}, ...}}`, with x and y as percentages. The value -1,-1 marks presence inside an instance. — local `QuestieDB\src\meta\npcMeta.lua`, `src\support\eraToForever.lua`
- `QuestieDB\src\support\eraToForever.lua` ("DBC bounds: 1.15.9.69722 -> 1.60.1.69893") provides `LibQuestieDB.EraToForever(areaId, x, y)` with linear transforms (scaleX, offsetX, scaleY, offsetY) for **Mulgore (215), Eastern Plaguelands (139), Redridge Mountains (44) and Stormwind City (1519)**. It is "never applied automatically to database reads" and comes with the warning "Do not convert Forever data again". — local file
- HereBeDragons-2.0 (bundled in Questie) builds a per-map `{width, height, left, top, instance}` from `C_Map.GetMapWorldSize` / `C_Map.GetWorldPosFromMapPos` at runtime. — local `Questie\Libs\HereBeDragons\HereBeDragons-2.0.lua`
- Zone ID mapping tables: `support\Forever\Zones\areaIdToUiMapId.lua` and `uiMapIdToAreaId.lua`. — local files

### Inferences
- Conversion: `worldX = left - (x/100)*width` and `worldY = top - (y/100)*height`, with WoW's axis conventions as used by HBD. In practice, distance in yards = `hypot(dx/100*width, dy/100*height)` within one zone.
- Getting the zone sizes offline: either (a) dump the HBD `mapData` table in game on the Forever client, which is the most reliable option, or (b) use the UiMapAssignment / WorldMapArea DBC from wago.tools for build 1.60.1.
- Cross-zone travel needs the continent frame (HBD `GetWorldCoordinatesFromZone`).
- Know whether a point is Era data or Forever data before applying `EraToForever`.

### Gaps
- Numeric zone dimensions were not extracted in this session, so they still need the in-game dump or the DBC export.
